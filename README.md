# ISO 29110 DocGen

> งานเสร็จตั้งนานแล้ว แต่เอกสารยังไม่มีสักแผ่น ...ใครเคยเป็นยกมือขึ้น

ทีมเล็กส่วนใหญ่ไม่ได้ขี้เกียจทำเอกสาร แค่ตอนทำงานจริงไม่มีใครว่างมานั่งพิมพ์ SOW, SRS, RTM ไปพร้อมกับเขียนโค้ด
พอใกล้วันตรวจ ISO ก็ต้องมานั่งไล่ความจำย้อนหลัง เปิด LINE หาวันที่ แก้ชื่อไฟล์ที่ copy มาจากโปรเจกต์เก่า
แล้วก็ภาวนาว่าผู้ตรวจจะไม่เปิดดูข้างใน

DocGen เกิดมาเพื่อตัดขั้นตอนนั้นทิ้ง คุณเล่าว่าโปรเจกต์ทำอะไรไปบ้างด้วยภาษาคน
ระบบจะถามต่อทีละขั้นจนได้ข้อมูลครบ แล้วจัดเอกสารตาม **ISO/IEC 29110 Basic Profile** ออกมาเป็น Word กับ Excel
หน้าตาแบบหนังสือราชการไทย พร้อมเซ็น พร้อมยื่น

---

## ทำอะไรได้บ้าง

```
 เล่าโปรเจกต์ ──▶ ตอบคำถามทีละขั้น ──▶ กดสร้างเอกสาร ──▶ ติดตามหลักฐาน ──▶ Export ไปยื่นตรวจ
   (ภาษาพูด)       (8 ขั้น PM/SI)       (27 รายการ)       (Ver/Val/Baseline)   (Evidence List)
```

**สัมภาษณ์แทนการกรอกฟอร์ม** ถามทีละไม่กี่ข้อ ตอบสั้น ๆ ได้ แปะอีเมลหรือโค้ดได้ ข้อไหนไม่รู้ก็ข้าม
มันจดไว้ว่ายังขาดอะไร แล้วไม่ถามซ้ำให้รำคาญ

**เอกสาร 27 รายการตาม Doc Mapping** SOW, Project Plan, SRS, Design, API Spec, RTM, Test Case, Test Report,
UAT, Change Request, Meeting Record, Acceptance, Installation Manual ฯลฯ ฟอนต์ TH Sarabun New
ขอบกระดาษแบบราชการ เลขหน้า "- ๒ -" บันทึกข้อความครบสูตร

**ไม่แต่งเรื่องให้** อันนี้สำคัญที่สุด ถ้าคุณไม่ได้บอก มันจะไม่เดาชื่อคน ไม่ใส่วันที่เอง ไม่สร้างผลเทสขึ้นมา
ช่องไหนข้อมูลไม่พอจะขึ้นเป็น `[ต้องระบุ: ...]` ให้เห็นจะ ๆ และวันที่จัดทำเอกสารย้อนหลังไม่ได้
เพราะเอกสารที่ดูดีแต่ไม่จริง พังหนักกว่าเอกสารที่ยังไม่ครบ

**ตรวจความพร้อมก่อนผู้ตรวจจะเจอ** เอกสารไหนยังไม่มี ช่องไหนยังว่าง หลักฐานไหนต้องให้ลูกค้าเซ็น
หรือแม้แต่ชื่อไฟล์ที่ยังติดรหัสโปรเจกต์เก่ามา (เจอบ่อยกว่าที่คิด)

**ทำงานเป็นทีม** มีบัญชีผู้ใช้ สิทธิ์ 3 ระดับ ทุกไฟล์และทุกคำตอบบอกได้ว่าใครทำ
พร้อม log ละเอียดยิบสำหรับคนที่ต้องตอบคำถามว่า "ใครแก้ไฟล์นี้ตอนไหน"

## เริ่มใช้ใน 3 นาที

```bash
git clone <repo> iso29110-docgen && cd iso29110-docgen
cp .env.example .env
```

เปิด `.env` แล้วใส่อย่างน้อยสามบรรทัดนี้

```ini
GEMINI_API_KEY=xxxxxxxx          # key ของ Google Gemini
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ตั้งให้ยาวหน่อย8ตัวขึ้นไป
```

แล้วรัน

```bash
docker compose up -d --build
```

เข้า **http://localhost:8290** ล็อกอินด้วย admin ที่เพิ่งตั้ง จบ

<details>
<summary>ไม่อยากใช้ Docker</summary>

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt     # macOS/Linux: .venv/bin/pip
.venv/Scripts/python -m app                       # อ่าน PORT จาก .env
```
</details>

## ค่าใน `.env`

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `PORT` | พอร์ตของเว็บ (ค่าเริ่มต้น 8290) docker compose ใช้ค่านี้ทั้งข้างในและข้างนอก |
| `GEMINI_API_KEY` | key สำหรับเรียก Gemini ถ้าไม่มีจะลองใช้ `GEMINI_LIVE_API_KEY` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | ผู้ดูแลระบบคนแรก สร้างให้ตอนเปิดโปรแกรมถ้ายังไม่มี บัญชีเดิมจะไม่ถูกเขียนทับ |
| `ADMIN_EMAIL` / `ADMIN_NAME` | อีเมลกับชื่อที่แสดงของ admin |
| `COOKIE_SECURE` | ตั้งเป็น `true` เมื่อเปิดผ่าน HTTPS |

อยากใช้ Vertex AI แทน API key ก็ได้ อัปโหลดไฟล์ service account ที่หน้า **ตั้งค่า → AI** แล้วสลับโหมด
ค่าใช้จ่ายจะไปเข้า GCP project ของคุณเอง

## หนึ่งวันกับ DocGen

1. **สร้างโครงการ** ใส่ชื่อ รหัส (เช่น `Toyota_LLMIntent-2026-001`) ลูกค้า และเล่าคร่าว ๆ สองสามบรรทัด
2. **ตอบคำถามทีละขั้น** 8 ขั้นตามกระบวนการ PM.1–PM.4 / SI.2–SI.6 ตอบไม่หมดก็ได้ วันหลังกลับมาต่อ
3. **กดสร้างเอกสาร** ตั้งชื่อไฟล์ ฉบับที่ และผู้ลงนามได้ก่อนกด ไม่พอใจก็สร้างใหม่เป็นฉบับถัดไป
   หรือโหลดไปแก้ใน Word แล้วอัปโหลดกลับเป็นฉบับใหม่ก็ได้
4. **อัปเดตสถานะหลักฐาน** ร่าง → ทวนสอบแล้ว → ลูกค้ายืนยันแล้ว → Baseline พร้อมแปะลิงก์ Drive
5. **ก่อนวันตรวจ** เปิดแท็บความพร้อม Audit ไล่เก็บที่ขาด แล้วโหลด ZIP ทั้งชุดพร้อม Evidence List

## ทีมและสิทธิ์

| บทบาท | ทำอะไรได้ |
|---|---|
| **admin** | ทุกอย่าง จัดการผู้ใช้ ดู log ตั้งค่าระบบ |
| **editor** | สัมภาษณ์ สร้าง แก้ ลบเอกสาร อัปเดตหลักฐาน |
| **viewer** | ดูและดาวน์โหลดอย่างเดียว เหมาะกับหัวหน้าหรือลูกค้าที่อยากตามงาน |

คนใหม่สมัครเองได้ แล้วรอ admin อนุมัติ (จะเปลี่ยนเป็นเปิดรับเลย หรือปิดรับสมัครก็ได้)
รหัสผ่านเก็บแบบ scrypt ล็อกอินผิดติดกันหลายครั้งจะโดนพักไป 15 นาที

**Log เก็บแทบทุกอย่าง** ใคร ทำอะไร เมื่อไหร่ จาก IP ไหน เบราว์เซอร์อะไร ส่งข้อมูลอะไรมา ผลเป็นยังไง ใช้เวลากี่มิลลิวินาที
ยกเว้นรหัสผ่านกับ key ที่ถูกปิดทับก่อนบันทึกเสมอ ค้นหา กรอง และ export เป็น CSV ได้จากหน้าจัดการระบบ

## ปรับให้เป็นของคุณ

ทุกอย่างอยู่ที่หน้า **ตั้งค่า** ไม่ต้องแก้โค้ด

- **เว็บไซต์** ชื่อ คำอธิบาย โลโก้ สีหลัก สีแถบด้านบน (ใครชอบโหมดมืดกดเปลี่ยนเองได้ที่มุมขวาบน)
- **ข้อมูลบริษัท** ชื่อที่ขึ้นหัวเอกสาร ชื่อย่อในชื่อไฟล์ ส่วนงานในบันทึกข้อความ เลขไทย
- **รูปแบบเอกสาร** แพทเทิร์นชื่อไฟล์ เช่น `{company}_{project}_{doc}{item}_v{version}`
  การนับฉบับ 1.0 → 1.1 หรือ 1.0 → 2.0 ฟอนต์ ขนาดตัวอักษร หน้าปก

## ข้อมูลอยู่ตรงไหน

| โฟลเดอร์ | มีอะไร | สำรองไหม |
|---|---|---|
| `data/` | ฐานข้อมูล SQLite (โครงการ ผู้ใช้ log) และ `config.json` | **ต้องสำรอง** |
| `storage/` | ไฟล์ .docx / .xlsx ที่สร้าง แยกตามโครงการและขั้น | **ต้องสำรอง** |
| `secrets/` | service account ของ Vertex AI | เก็บแยก อย่าเอาขึ้น git |

ทั้งสามโฟลเดอร์ถูก map ออกมาจาก container แล้ว ลบ container ทิ้งข้อมูลก็ยังอยู่

## เครื่องมือเสริม

`tools/log_summary.py` สรุป log ของระบบ production ให้กลายเป็นหลักฐานการทดสอบ
นับจำนวนสาย อัตราสำเร็จ เวลาตอบเฉลี่ยและ p95 ครั้งที่เกินเวลา และ error แยกประเภท ทุกตัวเลขมาจาก log จริง

```bash
python tools/log_summary.py ./logs result.xlsx --from 2026-09-01 --to 2026-09-30 --slow 3
```

## คำถามที่โดนถามบ่อย

**เอาเอกสารที่ได้ไปยื่นตรวจได้เลยไหม**
ได้ ถ้าเนื้อหาตรงกับที่เกิดขึ้นจริง ระบบช่วยจัดรูปแบบและไม่ปล่อยให้ข้อมูลที่ขาดหายไปเงียบ ๆ
แต่ลายเซ็น การทบทวน และการยืนยันจากลูกค้ายังต้องเกิดขึ้นจริง อันนั้นไม่มีโปรแกรมไหนทำแทนได้

**โปรเจกต์จบไปแล้วแต่ไม่มีเอกสารเลย ใช้ได้ไหม**
ได้ และเป็นเคสที่เจอบ่อยที่สุด ตอบตามที่จำได้ ส่วนที่ทำด้วยวาจาจะถูกบันทึกเป็น "จัดทำย้อนหลัง" ตรง ๆ
ผู้ตรวจรับได้มากกว่าเอกสารที่แก้วันที่ให้ดูเหมือนทำทันเวลา

**ข้อมูลลูกค้าออกไปข้างนอกไหม**
ข้อความที่ตอบในการสัมภาษณ์จะถูกส่งไปประมวลผลที่ Gemini ตอนถามและตอนสร้างเอกสาร
ถ้านโยบายบริษัทไม่อนุญาต ให้ใช้โหมด Vertex AI ในโปรเจกต์ GCP ขององค์กรเอง ส่วนไฟล์และฐานข้อมูลอยู่ในเครื่องคุณทั้งหมด

**ลืมรหัส admin**
ให้ admin อีกคนกดรีเซ็ตรหัสให้ หรือถ้าเหลือ admin คนเดียว ตั้ง `ADMIN_USERNAME` และ `ADMIN_EMAIL` ใน `.env`
เป็นชื่อกับอีเมลใหม่ที่ยังไม่เคยใช้ ใส่ `ADMIN_PASSWORD` แล้วเปิดโปรแกรมใหม่ จะได้ admin อีกคนไว้เข้าไปรีเซ็ตบัญชีเดิม
